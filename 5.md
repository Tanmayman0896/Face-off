# Step 5: Route Protection, Error Handling & End-to-End Verification

## Objective
Configure middleware route protection, robust server error handling, and conduct full end-to-end verification of the Tier-Based Question Application.

## Detailed Tasks

### 1. Middleware Route Protection (`middleware.ts`)
- Intercept incoming requests to `/dashboard` and `/tier/*`.
- Extract session token / Neon Auth cookie.
- If missing or invalid, redirect to landing page (`/`).
- Allow API and static asset requests to pass through.

### 2. Double-Guard Authorization & Error Handling
- Server Components and Server Actions must re-verify session and DB permissions independently (never trust middleware alone).
- Wrap database and action workflows in structured try-catch blocks.
- Map internal exceptions (e.g. unique constraint violations, database connection errors) to user-friendly safe messages (e.g., "This question has already been solved.", "Tier access denied.").

### 3. End-to-End Verification Checklist
- **Database & Migration**: Verify `drizzle-kit` schema matches PostgreSQL tables.
- **Seed Verification**: Confirm 3 tiers and 9 questions are populated.
- **Auth & Onboarding**:
  - Test registration/login.
  - Verify team creation and initial state (Tier 1 `UNLOCKED`, Tiers 2 & 3 `LOCKED`, balance 0).
- **Retry Mechanism**:
  - Submit wrong answer on Tier 1 Question 1 -> retries drop to 1.
  - Submit wrong answer again -> retries drop to 0, tier status set to `FAILED`.
- **Reward System**:
  - Submit correct answer -> balance increases by reward amount.
  - Resubmit same correct answer -> balance remains unchanged, error returned.
- **Tier Progression**:
  - Solve Questions 1, 2, and 3 in Tier 1 -> Tier 1 marked `COMPLETED`, Tier 2 automatically `UNLOCKED`.
  - Attempt URL access `/tier/3` while Tier 2 is locked -> server redirects back to `/dashboard`.
  - Complete Tier 2 -> Tier 3 `UNLOCKED`.
  - Complete Tier 3 -> Game Complete state.

## Acceptance Criteria
- [ ] Direct URL access to locked tiers is blocked server-side.
- [ ] Database updates survive page refresh, browser restart, and logout/login.
- [ ] No client-side answer leakage in network responses or DOM.
- [ ] Application compiles cleanly with zero TypeScript or build errors (`npm run build`).
