# Step 4: Question Interface & Server-Side Answer Validation

## Objective
Build the single-question interface and implement strict server-side answer validation, retry tracking, atomic reward distribution, and tier completion/unlocking.

## Detailed Tasks

### 1. Server-Side Question Retrieval (`app/tier/[tierId]/page.tsx`)
- Server Component validates:
  - User session & authenticated team.
  - Team tier access (`UNLOCKED` or `COMPLETED` status in `team_tiers`).
  - Remaining retries > 0 (if status is not `COMPLETED`).
- If tier is `LOCKED` or `FAILED`, server redirects immediately to `/dashboard`.
- Fetches active tier questions **EXCLUDING the `answer` column** from SQL output.
- Pass question text, ID, index (e.g. Question 2 of 3), reward amount, and current retries remaining to client component.

### 2. Question View Component (`components/QuestionView.tsx`)
- Displays current unsolved question.
- Header displaying question index (`Question X / 3`) and retries remaining (`Retries: X / 2`).
- Answer input field with submit button.
- Submits answer to Server Action `submitAnswer({ questionId, answer })`.
- Renders feedback banner on submission:
  - **Correct**: Displays `✓ Correct! +$XXX` and button to advance to next question or complete tier.
  - **Incorrect**: Displays `✕ Incorrect! Retries remaining: X`.

### 3. Server Action `submitAnswer({ questionId, answer })`
Execution pipeline:
1. Obtain authenticated `authUserId` from server session.
2. Query associated team record from `teams`.
3. Retrieve `question` record by `questionId` from DB (including DB answer and reward).
4. Retrieve `team_tiers` record for `(teamId, question.tierId)`:
   - Reject if status is `'LOCKED'` or `'FAILED'`.
   - Reject if `retriesRemaining <= 0`.
5. Execute atomic DB transaction:
   - Check if question has already been solved in `team_question_rewards`.
   - Record attempt in `question_attempts` (`submittedAnswer`, `isCorrect`).
   - **If Answer is CORRECT**:
     - If question not yet rewarded: insert row into `team_question_rewards` and increment team `balance` by `question.reward`.
     - Count total solved questions for this tier in `team_question_rewards`.
     - If total solved questions == 3:
       - Update current tier status to `'COMPLETED'` with `completedAt = now()`.
       - Query next tier (`tierNumber = current.tierNumber + 1`).
       - If next tier exists, update `team_tiers` status for next tier to `'UNLOCKED'`.
     - Return `{ isCorrect: true, reward: question.reward, tierCompleted, nextQuestionId }`.
   - **If Answer is INCORRECT**:
     - Decrement `retriesRemaining` by 1 in `team_tiers`.
     - If new `retriesRemaining == 0`, set tier status to `'FAILED'`.
     - Return `{ isCorrect: false, retriesRemaining: newCount, tierFailed: newCount === 0 }`.

## Critical Security Requirements
- **NO Client Validation**: Answers are never included in JS bundles, HTML, props, or API outputs.
- **No Duplicate Rewards**: Unique constraint on `team_question_rewards(teamId, questionId)` prevents double payouts across multiple tabs/requests.
- **No Unlocking Bypass**: Direct navigation to `/tier/2` or `/tier/3` without DB `'UNLOCKED'` status is blocked server-side.

## Acceptance Criteria
- [ ] Answer comparison occurs 100% server-side.
- [ ] Correct answer rewards digital money once and only once per question.
- [ ] Wrong answers consume 1 retry; 2 wrong answers set tier to `FAILED`.
- [ ] Solving all 3 questions completes tier and unlocks next tier in PostgreSQL.
